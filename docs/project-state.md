# Project State

## Project Overview

Job Tracker is a Nuxt 4 application for tracking job applications end to end. It is a fully client-side, local-first app: all data lives in IndexedDB in the browser (via Dexie.js), there is no server API and no authentication. The UI lets you create, edit, filter, search, inspect, update status, and delete entries, plus export/import the whole table as JSON.

Current stack:

- Nuxt 4 (client-only, `ssr: false`)
- Vue 3
- Nuxt UI 4
- Pinia
- Dexie.js (IndexedDB)
- TypeScript
- ESLint
- Prettier

## Important Decisions

- Node target is fixed to `>=24 <25`.
- Store all data client-side in IndexedDB via Dexie.js; no server, no auth, no `isDemo` split.
- `prisma/schema.prisma` (and `prisma/migrations/`) are kept only as documentation of the data shape that `app/lib/db/schema.ts` mirrors — they are no longer connected to any live database, generator, or client.
- UI job status labels, colors, and options live in `app/utils/job-statuses.ts`.
- Shared job application types and formatters live in `app/utils/job-applications.ts`.
- The status enum lives in `prisma/schema.prisma` (docs only) and is duplicated in `app/utils/job-statuses.ts`, so adding/removing statuses requires updating both by hand.
- The list page uses client-side filtering/searching so typing does not trigger loading churn.
- The status selector on the detail page replaces the duplicate badge.
- Demo data is regenerated with `npm run demo:generate` from fixtures in `scripts/generate-demo-data.mjs`; it seeds an empty local database once, on first run.
- Export/import (JSON, whole table, replace-all on import) lives on the `/jobs` page.

## Known Issues

- There are build warnings from external dependencies during `npm run build`:
  - Tailwind sourcemap warnings
  - `@vueuse/core` `#__PURE__` comment warnings
  - Node deprecation warnings from package export mappings
    These do not fail the build.
- Status changes still require coordination across the (docs-only) Prisma enum, the frontend status helper, and the demo seed fixtures.
- The app currently has no automated test suite beyond format/lint/build checks (the previous `test/server-api.test.ts` was removed along with the server API it exercised).
- A handful of `UButton`/`@click` handlers (`app/components/jobs/DeleteJob.vue`, `app/pages/jobs/index.vue`) have pre-existing `npm run typecheck` errors (event handler return type mismatches) that predate the local-first migration and were left as-is rather than folded into it.
